Descripción General

Una agencia inmobiliaria vende algo que el cliente solo compra dos o tres veces en su vida, y por un importe que le da miedo. Por eso su web no tiene que ser un catálogo: tiene que transmitir profesionalidad, confianza y claridad antes de pedir nada.

El sitio se estructura en torno a eso. Un hero con imagen panorámica de Valencia para situar geográficamente al visitante, una sección de servicios, la explicación paso a paso de cada proceso — comprar, vender, alquilar — para quitar incertidumbre, reseñas reales de clientes como prueba social, y al final una agenda de citas.

Está construido con HTML, CSS y JavaScript puros, sin ningún framework ni dependencia. Para una web corporativa de este tamaño eso significa carga inmediata y nada que actualizar dentro de dos años.

Arquitectura

Sitio estático de una página con plantillas parciales en templates/ y los recursos gráficos en SVG, que escalan sin pérdida y pesan una fracción de un PNG equivalente. Sin build, sin dependencias y sin gestor de paquetes.

Retos Técnicos y Decisiones de Diseño

Diseñar para quien no compra a menudo

El visitante de una inmobiliaria no sabe cómo funciona el proceso y eso le frena. La sección de procesos paso a paso existe precisamente para eso: explicar el recorrido completo antes de pedir sus datos. Es una decisión de contenido, no de diseño, y es la que más influye en que alguien pida cita.

SVG en lugar de imágenes de mapa de bits

El logo y el hero son SVG. Escalan a cualquier pantalla sin pixelarse, pesan mucho menos y se pueden recolorear desde CSS. En un sitio cuyo primer impacto es visual, el tiempo de carga del hero es parte del mensaje.

Cero dependencias, a propósito

Para una web corporativa estática, añadir un framework significa un proceso de compilación, dependencias que caducan y mantenimiento futuro sin ningún beneficio para el visitante. HTML, CSS y JavaScript funcionan igual dentro de cinco años.
