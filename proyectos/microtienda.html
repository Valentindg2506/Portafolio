Descripción General

Práctica de la asignatura de Sistemas de Gestión Empresarial, en la unidad de integración de módulos. El objetivo no es hacer una tienda bonita, es entender cómo tres piezas independientes —catálogo, carrito y datos del cliente— acaban consolidándose en una única estructura de datos lista para enviar a un sistema de gestión.

Ese es el núcleo del ejercicio: un objeto pedido con tres claves — cliente, productos y pedido — donde la última contiene el número generado con Date.now() y la fecha del sistema. Cada interacción del usuario va rellenando una parte de ese objeto.

El recorrido de diez pasos incluye también la parte de datos: la preparación del esquema MySQL, la asignación de permisos de base de datos y una versión final que sirve los productos dinámicamente desde PHP.

La Estructura del Pedido

  • pedido.cliente — nombre, apellidos y email, recogidos del formulario al pulsar enviar.
  • pedido.productos — array al que cada botón del catálogo añade el nombre y el precio del artículo.
  • pedido.pedido.numero — identificador generado con Date.now().
  • pedido.pedido.fecha — fecha del sistema formateada como año-mes-día.
  • El objeto completo queda listo para serializarse y enviarse a un sistema de gestión externo.

Progresión del Ejercicio

  • 001-002La tienda y su estilo: maquetación del catálogo.
  • 003-004JavaScript y comportamiento de los botones de compra.
  • 005Datos del cliente: el formulario que completa la parte de cliente.
  • 006Trabajo sobre el CSS.
  • 007Datos de pedido. La consolidación: el objeto único con cliente, productos, número y fecha.
  • 008-009Parte de datos: preparación del esquema MySQL y asignación de permisos de base de datos.
  • 010Productos dinámicos. El catálogo pasa a servirse desde PHP en lugar de estar escrito en el HTML.

Qué Aprendí

  • Que "integración de módulos" significa acordar una estructura de datos común: si el catálogo, el carrito y el formulario no coinciden en el formato, no hay integración posible.
  • Que Date.now() sirve como número de pedido en un ejercicio, y que en un sistema real haría falta un contador con garantías de unicidad.
  • Que asignar permisos de base de datos es parte del trabajo: un usuario de aplicación no debería tener los mismos privilegios que el administrador.
  • Que pasar de un catálogo escrito a mano en el HTML a uno servido desde PHP es el paso que convierte una maqueta en una aplicación.
